# 维修站角色动作

[新旧版本同步对照](compare.mp4)按游戏实际收到 F、D、Shift、W 和空格的时刻对齐两局。上面是旧版，下面是新版；每行左边放大角色，右边保留完整窗口。要单独看出拳，可打开[真机侧面连拍](side/punch.jpg)或[侧面短片](side/punch-side.mp4)。玩家按 F 会转向镜头所瞄的方向，因此另录的一局在起拳后拖动鼠标，移到角色侧面。第 60–62 帧能看清左拳的伸展，第 64 帧已经开始屈肘收回。

新版在出生点连续按两次 F，每次都进入 Station-Punch。两拳都挥空，主角没有移动。第一拳收完回到 Idle-cycle；第二拳结束时 D 刚好生效，直接转为 walking_gun-cycle。以髋为原点，向人物面朝的方向量左手指节相对起拳前的位置，两次最远分别前伸 0.873 和 0.859 米。右手留在身前。头部和相机都会转，借这个角色坐标能把转身和真正的手臂伸展区分开。[正式包完整录像](after/game.mp4) · [逐帧位置、动画与事件](after/frames.jsonl.gz) · [测量明细](after/measured.json)

接着看[正式包的走、跑和转向](after/gait.jpg)。玩家走了 2.62 米，按 Shift 后的观测段走了 2.16 米，改按 W 后身体转过 90.2 度。走路时，左脚相对右脚从后方 0.70 米摆到前方 0.64 米；奔跑时扩大到从后方 0.97 米到前方 0.99 米。同一局中黄色瓦特在跟随阶段移动了 3.91 米，两脚在前后方向也有换位。末尾原地跳起的高度差为 1.12 米。运动和姿势取自游戏中的实体与节点，场景不变，第二次录制只改变了观察相机的操作。[按键和画面对应的帧号](after/take.json) · [侧拍完整骨骼](side/frames.jsonl.gz)

平地滑步另查脚尖已经接近最低点的相邻两帧。从这两个位置的水平距离除以帧间隔，可以读到脚尖在地面上滑多快。在同一条路线，旧脚本搭配可观察骨骼的原生程序时，玩家走路有 17 个可用间隔，中位为 1.60 米/秒；最终发行包中有 4 个，中位为 0.13 米/秒。跑步这次没有连续两帧同时落在低位的样本。这组观测不足以推断其他地形和跑步时的落脚精度。最终包 SHA-256 为 b6332574a23e6158c62121540282719f3f40c70e6f81796ea3e4de945d30c896，两次实际使用了同一份 ZIP。

## 红色工具箱旁的脚尖

[跑步逐帧画面](after/feet.jpg)与[正常速度的短片](after/feet.mp4)取自 B6332574 构建。第 71–73 帧是右脚在背后摆动，第 75–77 帧轮到左脚。急转时右脚在第 79–81 帧、左脚在第 84–85 帧再次朝后。每一段中，这只脚的踝、趾都比它自己待机时的位置高至少 3 厘米。玩家步行与瓦特跟随的样本里，两只脚都未连续向后倒指。这里的“朝后”以每只脚在待机时的水平朝向为基准，先扣除人物本身的转向，再看脚趾有没有超过脚踝向后的距离，留出约 2 厘米以避开脚接近竖直时的微小偏差。[两位角色的膝角和踝趾坐标](after/feet.json)

右脚前三帧的运动可以在模型原始跑步剪辑里逐帧重现。左脚经过箱侧时出现另一种情况。第 75 帧，模型原片的左趾在踝前 0.07 米，实机到了踝后 0.13 米。第 76 帧原片也已经指向后方，但实际脚尖高 1.15 米，原片同一时刻只高 0.68 米。该帧以大腿、小腿和踝三个关节求得左膝弯曲 44.8 度，前后两帧分别为 115.5 和 106.1 度。第 77 帧脚尖高度又与原片一致。这三帧的异常抬高值得单独排查脚部对障碍物的处理。这里只量了踝到趾的长轴；鞋底绕这根轴的滚转需要再观察脚面的另一个点或脚骨旋转。[模型原片与引擎逐帧对照](after/authored-feet.json)

红箱的碰撞轮廓宽 0.78 米、深 0.60 米。在每一帧的角色髋部放回原片的脚踝，再用箱子的旋转和位置检查脚踝是否在箱子上方。整段里只有第 74–76 帧的左踝落在这个轮廓内，对应的额外抬高分别为 0.293、0.416 和 0.472 米。其余样本的差值均小于 0.01 毫米。这项检查也能发现一次看似正确、实际恰好从箱子另一侧跑过的复测。

## 旧版的实际表现

[旧包实机录像](before/game.mp4)从出生点开始。按住右键，把镜头移到蓝色玩家侧面，松开后连按两次 F。旧版里手仍垂在身边。随后按 D 向右走，保持 D 再按 Shift 加速，最后松开 D 改按 W。可以同时看玩家和左后方黄色瓦特的双脚。镜头的末尾还有一次原地跳跃和一次蹲伏。[旧包的拳部连拍](before/punch.jpg)与[行走、加速和转向](before/gait.jpg)都取自同一次游玩。

这次跑的是 Windows x64 Release 包内的场景、模型、游戏脚本和可执行文件。游戏窗口与 HUD 为 1920×1080，三维场景使用玩家可以自行选择的 720p。镜头借助游戏里的鼠标右键转动，键鼠通过试玩记录器送进游戏。录像每张照片保留到下一张实拍的时刻，共 180 张、10.832 秒，图片之间没有补帧。截图与游戏状态的读数前后可能相差一帧或更多，取样的两个帧号都在 take.json 中。

旧包中玩家向右走的 1.01 秒共移动 2.74 米，加速后的 0.70 秒移动 2.51 米。转弯前经过箱子，地形与物体会限制实际位移。瓦特跟了 4.33 米，玩家原地跳起后上下高度相差 1.12 米。这些是世界坐标中量出的实际距离。旧包的试玩记录没有骨骼字段，视频里能看见手脚，却无法从这份日志读出当时的剪辑和关节坐标。[位置与按键的逐帧原文](before/frames.jsonl.gz) · [输入及窗口截图帧号](before/take.json) · [汇总数据](before/measured.json)

为了查清旧角色两次按 F 时到底在播什么，另做了一次诊断。保留旧包里的关卡、模型和 C# 程序，将原生程序换成可观察骨骼的 Release 构建（SHA-256 前 12 位 a88c7f68c1b0）。两次按键时主角都在播放 Idle-cycle，左手指节相对髋部的最大前移分别为 0.002 米、0.029 米。玩家走、跑时分别读到了 walking_gun-cycle 和 running_gun-cycle，瓦特跟随时读到 walking_nogun-cycle。这组数字包含新原生程序的姿势处理，只用于查旧脚本、旧模型在同一原生程序下的表现。[额外诊断的逐帧骨骼](old-game-new-native/frames.jsonl.gz) · [采样记录](old-game-new-native/measured.json)

## 在另一份发行包上复测

从仓库根目录运行。第一条命令解压到临时目录，打开游戏，沿同一条路线操作；第二条读取这次保存的照片和状态，生成连拍及 MP4。需 Windows、Python、项目已有的 pywin32 和 Pillow，以及 NumPy 和 PATH 中的 FFmpeg。

~~~powershell
python tests/capture_player_motion.py output/releases/Redflag-Watt-Station-Win64.zip tmp/station-motion-take
python tests/review_player_motion.py tmp/station-motion-take tmp/station-motion-review --require-animation
python tests/check_player_feet.py tmp/station-motion-review --take tmp/station-motion-take
python tests/compare_authored_feet.py output/releases/Redflag-Watt-Station-Win64.zip tmp/station-motion-review --verify-toolbox
~~~

最后一条命令使用 SciPy 读取压缩包内同一份 glTF 模型，在游戏记录的剪辑时间重建脚部姿势。角色整段要留在地面，原片脚踝要经过箱子的轮廓。满足这两个条件后，才核对脚尖高度与原片的误差。测试允许相差 2 厘米，逐帧的实际差值保存在 authored-feet.json。

加上 `--require-animation` 时，两次出拳都要有起手、接触检查和收拳记录，手还要相对髋部实际前伸并回收。行走和奔跑时，脚相对角色朝向应交替出现在另一只脚前面。脚尖接近地面的样本还保留了水平移动距离和采样间隔，便于另查滑步。3 厘米是本测试在平地上选取低位脚尖的高度范围。录旧包时省去这个开关即可检查位移和录像。主角是实体 1101，瓦特是 1102，原始状态按实体编号关联到同一帧。
