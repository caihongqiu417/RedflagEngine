# 维修站队友的行动记录

同一张正式维修站地图里，玩家和瓦特起初各有一份医疗包。验证使用本机 Qwen3-VL-2B-Instruct 决策服务。两人相距 5.830 米时，单凭背包的最后数量看不出瓦特是否听懂了要求，因此同时记录谁迈步、走了多远，以及发生交接时的库存。下表中的位移是起点到交接点之间的直线距离。[三组实机回执、模型选择与位移](decisions.json)

| 玩家的原话 | 瓦特的位移 | 玩家的位移 | 交接经过 |
| --- | ---: | ---: | --- |
| 请把你背包里的一份医疗包送到我手上。 | 3.830 米 | 0 米 | 瓦特带药走近，进入两米范围后交付。 |
| 帮我留一份医疗包，等我过来再给我。 | 0 米 | 4.455 米 | 瓦特原地保管至少三秒，等玩家走近后交付。 |

两次交接都只移动一份药。瓦特的库存由 1 变为 0，玩家由 1 变为 2。两句话均由真正的模型处理；节点 3 会以最新的候选再询问一次。早先的解包窗口里两人刚好相邻，玩家要求送药时模型选了“留药”，交接依然发生。这次角色设置分别写清了留药时谁来取、配送时谁上门，也给两项工作共用的子树加了追问。以后修改角色语言时，用这两句和不同站位一起回归。

第三组用例在瓦特进入补给子树、等待第二个回答时，让玩家从合法的拾取距离先拿走工具箱。回执保留了模型选择的原编号 1112；轮到场景确认时，这个物品已经不在。附近没有同类目标，瓦特恢复跟随，自己的背包没有增加。接下来让正式的伤害接口将玩家生命降至零，瓦特取消仍在等待的原地待命请求，按场景配置完成两秒救助，将玩家恢复到 50 点生命。手动取消另一条请求后继续更新两秒，旧回答也没有重新启动动作。[原生测试及输入](../../../tests/StationCompanionTests.cpp)

另用正式 Forge 通过 `--vulkan --play` 打开维修站，在真实游戏脚本、物理与渲染都运行的情况下录制 160 帧。没有发令，瓦特按角色约定跟上玩家，在交互距离内停下。其余三个用例读取同一正式场景，通过原生场景、PhysX、模型服务与角色系统做可重复的时序检查。用例控制玩家的移动、输入和环境伤害，队友始终由引擎里的角色系统控制。[正式游戏窗口的逐帧记录摘要](game.json)

在仓库根目录构建正式 Debug x64 引擎与 Forge。启动真实决策服务后，用以下命令重跑。脚本把三份原生运行日志和整个游戏会话保存在新建的临时目录，并将摘要写到本目录。

```powershell
python tests/check_station_companion.py --port 8716
tests/run_behavior_tree.cmd
```

这组测试覆盖表中两句中文、原地待命、恢复跟随、取消和补给被取走。模型或其量化版本变更后，应重新核对回答和行走距离。角色开始跟随、发生紧急救助、以及所有库存的变更，都可以分别从回执中看到。

## 没有发令时的提醒

在同一座维修站里，把玩家放到巡检机身旁，瓦特放在能看见它的位置。原生宿主启用正式 C# 游戏脚本。巡检机自行播放放电动作并让玩家生命从 100 变为 88。五组都没有给瓦特发行动指令，结束时瓦特仍在跟随。通常模型会选择电台提示。仅把玩家的「提醒方式」改为“保持安静，只在记录里记下”，同一个模型就选择静默，回执里不再有待播语音。两次都只记录了一次持续的放电。[实测的可播文字与实体编号](watch.json)

第三组在瓦特与巡检机之间加一块隔板，第四组让瓦特背向巡检机。玩家仍受到相同的伤害，瓦特两次都没有看到放电，也没有发出提醒。最后一组在瓦特认出动作、模型回答之前移开玩家。巡检机自行结束放电，场景收到回复后放弃已经过时的报点。这里验证到交给队友面板的文字和语音事件，扬声器的播放时长另有专门测试。短于 0.2 秒的动作可能发生在两次观察之间。[实机声音记录](../playtest-audio)

在仓库根目录运行 `python tests/check_station_companion.py --watch --port 8716`。场景起点、遮挡体的尺寸以及各组断言都在 `StationCompanionTests.cpp` 的 `Watch` 函数中；帧号从开始更新游戏的第一帧计数，不能换算成模型耗时。[测试场景摆位](../../../tests/StationCompanionTests.cpp)
