# Sponza 中庭的天空与环境反射

四张图都是正式 Vulkan 编辑器显示的场景图。相机位于中庭一端，面向另一端的拱廊。抬头看画面正上方，两排屋檐之间有一小块可以直接看到室外的地方。看材质时可以把目光移到近处的吊灯和两侧的装饰物上。

| 画面 | 对照位置 |
| --- | --- |
| [原场景](before.png) | 屋檐之间呈纯黑，当时的场景文件没有指定环境图。 |
| [加入天空，关闭镜面 IBL](sky-no-specular.png) | 屋顶开口显示环境图；模型保留直接光和探针照明。 |
| [新版默认设置](after.png) | 与上一张使用同一幅天空，模型还会从环境图读取镜面反射的颜色。 |
| [仅隐藏天空](hidden.png) | 屋顶开口重新呈黑色；吊灯仍能反射环境光。 |

为了分清“看到了天空”和“材质反射了天空”，第二、三张只切换镜面 IBL。旧版保留当时的显示方式，三张新版对照都使用 ACES 拟合，曝光为 0 EV。四次都在同一台机器上用 RenderDoc 1.47 抓取第 24 帧，固定场景图为 640 × 410 像素。脚本从四帧的材质图里找出都没有画到几何体的像素，再移除画面边缘和模型轮廓旁的两个像素。这样就能在不同场景与机位下自动选取天空，也能避开 TAA 混入屋檐颜色的地方。模型样本取自材质图里画有几何体的像素，单列了金属度高于 0.5 的部分。比较模型时从色调映射前的 RGB 算线性亮度；表中的图片经过色调映射，更便于直接观察。[像素统计和截帧事件](comparison.json)

默认机位一共选出了 2,575 个背景像素。旧图里它们全黑，新图的平均颜色为 RGB (172, 197, 226)，范围按每个颜色分量 0 到 255 表示。打开、关闭镜面 IBL 时，这些天空像素的颜色逐点相同。观察模型则有差别：14,904 个金属度高于 0.5 的像素中，14,870 个的线性亮度增量超过 0.001。最后只关掉天空显示，这时 254,938 个远离轮廓的模型像素与开天空时逐通道完全一致。

还换了一个没有建筑物的场景。把同一张天空图指定给 Stanford 兔子场景的临时副本，用它自己的相机重跑，画幅为 320 × 205。脚本从背景自动选出 29,173 个天空像素；关闭天空显示后，31,595 个远离物体轮廓的模型像素仍然逐通道相同。[兔子与远处的云层](bunny.png) · [兔子场景的四帧统计](bunny.json)

## 同一份光照的两种显示效果

打开[Reinhard 实机图](reinhard.png)和[ACES 拟合实机图](after.png)，看中庭左右两侧的帷幔。两次都保留天空、镜面反射与 0 EV 曝光，两张图送到显示着色器之前的线性 RGB 逐项完全相同。我们从材质图里挑出底色足够鲜明、红色或蓝色占优的像素，按同一批位置比较。这里用最大颜色分量与最小分量的差除以最大分量，得到 0 到 1 的饱和度；筛底色时取大于 0.65 的样本，量最终画面时用面板实际输出的 RGB。

红色样本的平均显示饱和度从 0.282 升到 0.472，蓝色从 0.381 升到 0.518。蓝色样本的显示 RGB 中位数由 (72, 85, 113) 变为 (73, 98, 148)。亮处也有代价：262,400 个像素中，至少一个颜色分量量化到 255 的像素从 0 增到 154。这个对照解释的是本机位最终画面中颜色的变化；墙面挡住了多少天光，要另外检查光照和反射。[两帧记录与统计](curves.json)

## 在本机复现

在仓库根目录运行。先准备好 Sponza 模型、Debug 或 Release 编辑器和 RenderDoc 1.47。下面的第一条命令要用改动前的可执行文件、场景文件和同名的 `.render.yaml`；这次基线对应提交 `503184c`。把导出目录交给第二条命令，再用新版可执行文件运行三个同机位的对照。脚本会保留默认场景，并另外复制两份，分别关闭镜面 IBL 和天空显示。四个完整的 `.rdc` 文件比较大，默认保存到本机的 `output/captures/local/`。各文件的具体位置和绘制事件在统计文件里。换机位或换场景时先重新捕获同机位的旧图，然后用 `--scene` 指向对应的新场景，`--out` 另选保存目录。

```powershell
python tests/capture_material_studio.py --exe <旧版编辑器.exe> --scene <旧场景.redflag> --width 640 --renderdoc tmp/tools/renderdoc/RenderDoc_1.47_64
python tests/check_atrium_sky.py --before-work <上一步打印的replay.json所在目录> --exe <新版编辑器.exe>
```

要复核两条显示曲线，再复制一份新版场景，将副本的渲染设置改为 `ToneMapping: Reinhard`，保留 `ExposureEV: 0`；用上面的截帧脚本和同一新版可执行文件导出它。在仓库根目录运行下面的命令，读取 Reinhard 与 ACES 两个导出目录，先比较 HDR 原值，再计算显示颜色。

```powershell
python tests/check_display_curve.py --reinhard <Reinhard的导出目录> --aces <新版默认场景的导出目录> --out output/validation/atrium-sky
```
