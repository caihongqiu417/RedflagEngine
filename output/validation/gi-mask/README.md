# 透过布片的光

这块布由两个三角形组成。中央 6×6 个纹素的透明度为零。将布铺在白墙和点光源之间，再把相机放在灯的位置，能依次核对眼睛看到的孔、鼠标点到的物体和墙上照亮的位置。视口为 64×64 像素。布在画面里占 38×38 像素，中央的孔占 14×14 像素。图是 Vulkan 的 GPU 读回结果，每张直接光图都把线性红通道 0.26 显示为白色。

原先能点到孔后的白墙，但这 196 个像素收到的直接光都是零。修正后，它们全都收到与移走布片相同的光，线性红通道平均为 0.25452444。再把一个实心方片放到孔后，方片覆盖的 64 个像素重新变暗，其余 132 个仍然亮。主绘制用正常的材质与拾取附件。检查阴影时只把白墙画入表面位置图，布和后方的小片仍留在射线遍历的三角形中。[改前读数](baseline.json) · [全部材质与像素读数](after.json)

镜面测试把灯牌、布和挡板放在相机背后。相机之前只有一面光滑镜子，输入的屏幕颜色全部为零。打开 SSR 的场景追踪后，镜面中央穿过孔，读到灯牌设置的线性 RGB（4，0.5，0.125）。换成实心板，或在原来的孔后放另一块板，同一个点都变为零。下图都用线性 RGB 除以 4 输出，对比时曝光保持相同。

为了量出穿过布孔的光，再把白墙放到 z = 0、布放到 z = 0.5、灯牌放到 z = 1。房间里的一个探针位于（0.0833，0.1667，0.3571），正对灯牌的半球发出 64 条光线。灯牌每次命中返回线性红通道 4，其他表面均不发光。只烘焙一轮，探针读到 2.0625，因此有 64 × 2.0625 ÷ 4 = 33 条光线到达灯牌。封孔以后，原处读到零。两次烘焙均把全部 504 个探针的六个方向读回，与保存的文件正文逐字节相同。

同一份带孔设置可以读回之前保存的探针。仅把裁剪值从 0.5 调到 0.75，或替换、移除独立的透明度图，旧文件都会被拒用。取消材质覆盖后，原文件又能读回。读者可在 `after.json` 的 `probe_loads` 核对这六次尝试，在 `probes` 找到探针的坐标和线性 RGB。[开孔的烘焙](open-fence.rfprobes) · [封孔的烘焙](sealed-fence.rfprobes)

测试从编辑器实际使用的 `CollectModels` 获取模型和材质，再进入同一套 Vulkan 绘制和 GI 计算代码。16 组对照覆盖 glTF 底图的透明度、OBJ 的独立透明度图、移除及替换贴图、材质与实体透明度相乘、恰好等于裁剪值，以及完全实心的材质。每组比较全部 4,096 个像素，表面位置比较容许 0.0001 个场景单位的浮点差，线性红通道容许 0.00001 的差。所有位置都在相应范围内。拾取另从真正在面板使用的实体编号图读回，包括孔内完整的 196 个位置。

## 复现

在仓库根目录，先编译 Debug x64 的 Redflag，再运行下列命令。测试在 `bin-int/Tests/gi-mask` 重建场景，使用 Python、Pillow 和 NumPy 读取 GPU 写出的浮点数组。测试使用隐藏窗口，调用与正式 Vulkan 后端相同的 `VulkanDraw`、`GlobalIllumination` 和 `ScreenEffects`。本组数字用于验证画面，计时见性能册。

```bat
tests\run_gi_mask_tests.cmd
```

要同时截帧，把 RenderDoc 的 DLL 路径作为第一个实参。保持工作目录在仓库根目录，随后用同版本 RenderDoc 回放。第二条命令会比较运行时与回放导出的 GPU 缓冲区，结果写入 `replay.json`。

```bat
tests\run_gi_mask_tests.cmd "C:\Program Files\RenderDoc\renderdoc.dll"
"C:\Program Files\RenderDoc\qrenderdoc.exe" --python tests\replay_gi_mask.py
```

本次在 NVIDIA GeForce RTX 5070 Ti Laptop GPU、Vulkan 1.4.0 上验证。RenderDoc 1.47 的事件 9 求最近表面，25 和 30 绘制布与白墙，42 读出可见表面。事件 58 单画白墙，70 读出白墙位置，82 计算各处是否能看见点光源。回放中的表面坐标和最终颜色与程序运行时的浮点数组逐字节相同。[原始帧](Mask_capture.rdc) · [回放与逐点核对](replay.json) · [测试源码](../../../tests/GIMaskTests.cpp)

本机的 renderdoc-mcp 0.3.0 使用较早的 Vulkan 截帧格式。使用它自带的 DLL 重新捕获相同的绘制后，MCP 读到了 3 次绘制及 0 条调试消息，这次的全部像素断言也通过。需要用 MCP 时打开这份单独保存的帧。[MCP 兼容帧](mcp-capture.rdc) · [事件概览](capture-overview.json)
