入门示例

创建实体，保存并重新打开场景

场景持有实体和组件。创建门时，场景已经为它准备了变换组件。下面让门在 X 轴上向右移动两个单位，再把场景写到 Forge 的资源目录。 

auto scene = Redflag::CreateRef<Redflag::Scene>();
auto door = scene->CreateEntity("Door");
auto& pose = door.GetComponent<Redflag::TransformComponent>();
pose.Translation.x = 2.0f;
Redflag::SceneSerializer(scene).Serialize("assets/scenes/Door.redflag");

auto opened = Redflag::CreateRef<Redflag::Scene>();
opened->OnViewportResize(1280, 720);
bool loaded = Redflag::SceneSerializer(opened).Deserialize("assets/scenes/Door.redflag");

示例假设工作目录是 RedflagForge。这里用文本场景的 Serialize 和 Deserialize。名字带 Runtime 的二进制序列化入口尚留有 TODO。打开含主相机的场景前先告诉场景面板的像素大小，相机读取时就会用它算投影。仅有变换的门还没有可绘制的外形。

给实体添加网格和材质

应用已经建立图形设备后，给刚才的门添加网格组件。这次直接使用内建立方体，材质设为红棕色。更改粗糙度会影响提供光照计算的绘制路径。 

auto& mesh = door.AddComponent<Redflag::MeshRendererComponent>();
mesh.MeshData = Redflag::Mesh::CreateCube();
mesh.Mat = Redflag::Material::Create(glm::vec4(0.66f, 0.24f, 0.12f, 1.0f));
mesh.Mat->Roughness = 0.75f;

从文件导入整扇门时，用 ModelRendererComponent 保存模型编号，部件材质由加载好的 Model 提供。需要单独调门把手时，在对应的子网格位置设置 OverrideMaterials。编辑结束后再次调用 Serialize，模型和材质设置才会写入场景文件。

用 C# 移动运行中的实体

在脚本工程中继承 Entity，把编译后的脚本类挂到实体上。运行场景后，引擎把两次更新之间经过的秒数传给 OnUpdate。按住 D 一秒，下面的脚本让实体沿 X 轴移动约两个单位。 

using Redflag;

namespace Sandbox {
    public class MoveDoor : Entity {
        void OnUpdate(float dt) {
            if (!Input.IsKeyDown(KeyCode.D)) return;
            var pose = GetComponent<TransformComponent>();
            var position = pose.Translation;
            position.X += 2.0f * dt;
            pose.Translation = position;
        }
    }
}

Translation 返回一份 Vector3 值，最后的赋值把新位置写回引擎。选“C# 脚本”可以查找脚本可用的属性与键名。

调节环境遮蔽与反射阴影图

在 OpenGL 场景渲染器初始化后，可以开关环境遮蔽，或者调整 RSM 间接光强度。前者影响角落与相邻表面的明暗，后者改变从带颜色的墙面反射到周围物体上的光。 

Redflag::SceneRenderer::GetSSAOEnabled() = true;
auto& indirect = Redflag::SceneRenderer::GetRSMSettings();
indirect.Enabled = true;
indirect.Intensity = 1.0f;

Vulkan 计算效果通过计算设备与各效果自己的设置工作。找 GPU 可写图像时搜索 CreateImage，查一次计算如何开始时搜索 Dispatch。着色器所需的资源按绑定编号排列，调度时的三个整数表示工作组数。

调节时间抗锯齿，清除上一视角的历史

时间抗锯齿（TAA）把本次算出的颜色与上一帧留下的颜色结合。连续几帧观察同一条边时，可以利用那些稍有偏移的采样点。切换场景或直接把相机从屋内移到屋外时，上一张图已是另一处景物，需要清除历史。 

// effects 是当前场景面板持有的 ScreenEffects。
effects.GetSettings().HistoryWeight = 0.85f;
effects.ResetHistory();  // 切换场景或跳切相机时调用一次。

画面正常更新时保留历史。每帧先调用 JitterProjection 取得这次略有偏移的投影，用同一个投影绘制场景并交给 Render。再把偏移前的投影传入 stableProjection，让同一机位的两次采样可以在同一像素累积。这个例子用 Vulkan 计算设备执行。

在 Vulkan 编辑器中用原生分辨率查看光照

从 RedflagForge 目录启动编辑器，在“渲染设置 Lighting”面板顶部选择“组合光照 Lit”。展开“质量与参数”，把“分辨率”设为“原始 Native”，着色计算就会使用场景面板的实际像素。选择“主相机 Game”可以观察场景保存的机位，选择“场景 Scene”可以绕着模型观察。

cd RedflagForge
..\bin\Debug-windows-x86_64\RedflagForge\RedflagForge.exe --vulkan

点 Sponza 视口上方的“实时效果”，直接光选“全部光源”，间接光选“DDGI”。勾选“对照：只显示直接光”，再取消勾选，比较两次墙角的亮度。GTAO 对周围几何遮住的部分减弱间接光，SSR 在画面中寻找倒影，TAA 用前几帧的颜色平滑边缘。打开快速导航时，移动镜头会先显示直接光，停下后恢复组合光照。

在“文件”菜单中选“保存”，同名的 .redflag.render.yaml 会保留模式、分辨率和效果参数。下次打开场景便可继续比较。初次使用 Sponza 需要在仓库根目录运行 python tests/fetch_sponza.py 获取模型。

让箱子落地，并同步给另一位玩家

打开 Physics-Workshop 场景，红箱子有动态刚体，地面有静态刚体。游戏层调用一次 OnSimulationStart() 建立碰撞体，随后每帧用 OnUpdatePhysics(dt) 推进物理。此时读箱子的 Transform 就能得到它落下后的姿态。退出模拟时调用 OnSimulationStop() 释放这次模拟用的对象。

主机连接 REDFServer 后，先用 CapturePoses(scene, ids) 读取这一刻要发的实体，再用 WorldClient::Publish 提交。上一份还在等待确认时，主机可以继续模拟。观看端每帧调用 Update()，收到新版本后用 NetworkScene::Apply 把位置写入自己的场景。两端按相同的实体编号认出箱子。

播放角色动作与驱动物理双腿

BVH 动作文件保存骨架的父子关系和每一帧的关节姿势。AnimationClip::LoadBVH 读取它们，Skeleton 把关节相对父骨的姿势换成模型中的位置。给皮肤上的顶点指定关节权重后，SkinnedMesh::Deform 就能随骨架弯曲模型。角色演示从待机和走路动作开始，还可切换到双腿的物理模拟。

在 Forge 打开 Character-Walk.redflag 可以观察骨架。按 F5 开始模拟，点场景面板后用方向键移动。在属性面板还可以暂停播放或拖动进度。想看带皮肤的模型，打开 Character-Fox.redflag，在狐狸身上选择 Walk 或 Run。共享的 ModelAnimation 保存骨架、顶点权重和所有动作。每个实体有自己的 ModelAnimationComponent，两只狐狸可以在不同时间播放不同动作。

打开 Character-Physics.redflag 可以查看物理行走。带 RagdollComponent 的角色由场景在每个物理步调用 Ragdoll::DriveWalk(seconds, speed)。速度以米每秒计。髋、膝、踝的驱动和脚底接触决定实际位移。关闭行走会放松关节，双腿随重力倒下。

从 NPC 视角找到可拿取的物体

物理实验台的候选图片在游戏开始前生成。AskNpcVision 接收场景名称和问题，在工作线程等待图片服务的回答。游戏继续绘制，等结果准备好后回到场景线程，按候选编号调用 CanPickUp。这个函数用当前的可拿取组件、手到物体的距离以及中间的遮挡决定能否拿取。箱子即使仍出现在旧照片里，游戏删除它以后查询也会失败。

如果问题是“地台右侧在哪里”，可以用 AskNpcCandidate 同时查询实体和已标注的图片区域。区域的 Origin 是拍摄位置，Direction 指向图片中选中的地方。从那里看过去可以认出目标所在的大致方向。一张照片只能给出这条射线，目标有多远仍需由场景里的几何来确定。

后端、平台与接口状态

RHI 是两种后端之间的公共约定。网格和纹理创建、索引绘制已有 OpenGL 和 Vulkan 实现。ComputeDevice 当前使用 Vulkan，同步 Dispatch 返回时结果可以读回。OpenGL SceneRenderer 与其后处理设置属于现有 OpenGL 绘制路径。WindowsWindow 管理桌面窗口，Forge 下的类负责编辑器交互。ScriptCore 的公开类型供 C# 使用，脚本可以访问已注册的托管接口。

索引取自本次生成时的源码，列出公开声明与重载。平台目录也包含供后端内部协作的类型。类名出现在索引中表示有相应声明，功能是否接入编辑器要结合调用点和测试判断。
