# 正交相机转动后的 TAA 拖影

两次运行在同一台 RTX 5070 Ti Laptop GPU 和 Windows Debug x64 构建上完成。128×64 双帧场景先绘制红挡板和蓝墙，再水平移动相机 1.60 个场景单位、转动 12 度。挡板在 z = −7，墙在 z = −8。正交画幅宽 8、高 4。透视相机在墙面处有相同的图幅。场景走编辑器使用的 Vulkan 网格绘制、位置重建和 TAA；把实际画出的物体底色直接作为 TAA 输入，以便辨认每个点来自哪一帧。这一组只验颜色和采样位置。

| 镜头与读数 | 修前 | 修后 |
|---|---:|---:|
| 正交：54 个刚露出墙面的像素中，错误接受旧帧的个数 | 54 | 0 |
| 正交：旧帧四个邻居都在蓝墙上、历史权重高于 0.4 的像素个数 | 3,795 | 3,795 |
| 正交：刚露出的墙上最大红色分量误差（线性 RGB） | 0.4 | 0 |
| 正交：单独放在观察深度 0.15 的墙面，视图横纵各平移半像素，中心的历史权重 | 0 | 0.5 |
| 透视：96 个刚露出墙面的像素中，错误接受旧帧的个数 | 0 | 0 |
| 透视：旧帧四个邻居都在蓝墙上、历史权重高于 0.4 的像素个数 | 3,738 | 3,738 |

测试在当前帧找蓝墙上的点，把它投到上一帧。如果周围四个旧像素全是红挡板，任何旧颜色都会造成错误。着色器结果第四个分量保存实际使用的历史权重，三通道保存混合后的线性 RGB。颜色会经过邻域限制，仅检查 RGB 可能看不出错误接受的历史。额外的投影抖动测试按屏幕左上角为原点，在 0.2、1、8、24 个单位深度检查前三个 Halton 采样点。正交和透视的最大位置误差分别为 0.00000402 和 0.00000127 像素。

使用 RenderDoc 1.47 打开 [修前帧](old/TAA-Ortho_capture.rdc) 或 [修后帧](fixed/TAA-Ortho_capture.rdc)，选事件 8 的 Dispatch（16×8×1 组），在计算着色器可写缓冲区中查看 Result（binding 5）。每项为一个 float4。像素 (1,32) 对应下标 4097，修前为 (0.50, 0.185, 0.43, 0.5)，修后为 (0.10, 0.25, 0.80, 0)。[原始回放读数及文件摘要](renderdoc.json) 包含两个事件的验证消息。old 和 fixed 各保存两种镜头的两张原始输入和 TAA 结果 PNG，两次输入逐像素相同。两张 edge 图只裁取第二帧像素 x = 0…6、y = 29…34 并做最近邻放大。另将真实 Sponza 透视镜头修复前后的 20 份 RGBA 浮点输出逐元素比较，结果见 [逐帧差值](sponza-regression.json)。

在仓库根目录用 Debug x64 构建 Redflag。运行 `tests\run_taa_camera_tests.cmd`，新的读数和图片写入 `tmp/taa-camera`。若要同时抓帧，追加输出目录与本机 RenderDoc DLL 的绝对路径，例如 `tests\run_taa_camera_tests.cmd tmp\taa-capture "C:\Program Files\RenderDoc\renderdoc.dll"`。测试的两次绘制与独立位置检查见 [TAACameraTests.cpp](../../../tests/TAACameraTests.cpp)，实际筛选距离的代码见 [TAA.comp](../../../Redflag/src/Redflag/Renderer/ScreenSpace/Shaders/TAA.comp)。
