# Vulkan 灯牌的表面与倒影

这组测试把光栅读出的灯牌颜色保留在线性空间中。数值 4 表示当前参考亮度的四倍，屏幕上经过色调映射的 PNG 无法直接读出这个数。设备为 RTX 5070 Ti Laptop GPU，Debug x64、Vulkan 验证开启。

## 材质和遮挡

在 96 × 64 的画面里铺一个正面朝向相机的矩形，给它三条宽色带，发光颜色设为 (4, 0.48, 0.14)。底图另有固定的反射光。读回实际合成结果后减去同一像素的底图颜色，得到下表。坐标从左上角起算。

| 纹理字节 | 采样坐标 | 线性红 | 线性绿 | 线性蓝 |
| --- | --- | ---: | ---: | ---: |
| 0 | (16, 32) | 0 | 0 | 0 |
| 128 | (48, 32) | 0.863281 | 0.103594 | 0.0302148 |
| 255 | (80, 32) | 4 | 0.48 | 0.14 |

按 sRGB 公式，输入 128 对应约 0.21586 的线性亮度，乘 4 得 0.86344。显卡实际取样得到 0.863281。在灯牌前放一块不透明面，三个位置都只剩原有的反射光；把前景透明度设为 0.25、裁剪门槛设为 0.5，三条色带重新出现。把灯牌翻过来，单面材质的背面发光为零，勾选双面后仍能读到相同强度。

半透明测试沿用两个倾斜玻璃面，将各层的自发光红色设为 2。重叠处的覆盖率为 1 − (1 − 0.22) × (1 − 0.35) = 0.493。两层合成后，这个像素的红色比关闭发光时增加 0.986。[GPU 读回记录](rhi.txt)

## 屏幕空间反射

第二个测试把一条灯牌放在 160 × 64 画面的第 53 至 80 列，先光栅化实际发光图，再加进本帧的颜色。左边镜面的反射光线碰到灯牌，读到的红色随材质反射率降到 3.40905。右边镜面的光线离开屏幕，此次测试关闭了环境光，读到黑色。[SSR 命中和未命中像素](reflection.csv)

从仓库根目录执行 `tests\run_rhi_tests.cmd` 和 `tests\run_environment_lighting.cmd tmp\emission-check`。前者同时检查无发光材质、单面与双面、透明裁剪和拾取。后者使用已有的镜面实验，可从输出目录的 `measurements.csv` 读取两项灯牌记录。三条色带由测试按与展示模型相同的字节值制作，屏幕反射的两条镜面位置由测试给定。完整编辑器里的导入和显示应另对照展示场景。[本轮测试程序和内嵌着色器摘要](sha256.txt)

只有显示画面需要表面自身的光、场景也确实提交了实心发光材质时，编辑器才创建发光图。火盆复用主绘制写下的深度，普通墙和柱子省去第二次绘制。两片几何恰好共面时，主绘制在底色图第四项的符号位记下胜出的材质是否发光；读取金属度与粗糙度仍用其绝对值。两块共面的灯牌则保留先通过深度测试的那块。GPU 用例分别覆盖了普通墙和两个不同颜色的灯牌。纯间接光视图保留间接光结果，组合光照会在 SSR 查找反射物前加好灯牌颜色。玻璃的自发光随玻璃单独合成。

## 神庙火盆

正式编辑器打开 Sun Temple，使用场景保存的机位、全部点光源、DDGI、GTAO 和 TAA，光照图为 800 × 513。第 24 帧仍在像素内取不同的位置，两版都要重新绘制。比较第一次完成的发光实现与共享深度的版本，GPU 发光绘制从 48 次降到 4 次，索引从 1,819,128 个降到 202,122 个。主表面和拾取各画 48 次，界面画 22 次。原版发光通道另有一张 D32 深度图，新版的深度资源 ID 与主表面相同，按像素格式少用 1.57 MiB。发光颜色图和合成结果仍各需 6.26 MiB。[实际面板](temple.png) · [火盆的非零发光像素](temple-emission.png) · [绘制事件、资源、原始帧路径与 SHA-256](temple.json)

在 RTX 5070 Ti Laptop GPU 上暂时关闭其他图形测试，对每份 RenderDoc 1.47 捕获先热身一次，再读取 11 次 GPU 计数器。每次把该帧发光绘制的 GPU 时间相加，中位数为 169.728 和 16.832 微秒。合成阶段从 10.752 增至 16.288 微秒，多读的一张底色图区分恰好共面的发光与普通材质。前后顶点步长是 44 和 52 字节，新版还允许发光图使用另一套 UV。CPU 时间只记录了这一帧内各次 Vulkan 绘制 API 的调用时长之和，旧版 121 微秒、新版 32 微秒，含截帧层与验证开销。[GPU 各次读数与 CPU 单次记录](temple.json)

两版神庙的线性 HDR RGB 与面板 RGBA 均逐字节相同。另以没有声明任何发光参数的 AntiqueCamera 运行正式摄影棚，较早版本与本次版本各有 29 次绘制和 9 次计算，底色、线性光照、显示颜色相同。[两组输入及像素校验](pixels.json)

在仓库根目录运行以下 PowerShell 命令可重新截帧。历史 Debug 可执行文件保存在本机，摘要见 `sha256.txt`。捕获程序会打印工作目录和原帧路径。把两份神庙工作目录赋给下面同名的环境变量，便可回放另外一组输入。

```powershell
$rd = 'tmp/tools/renderdoc/RenderDoc_1.47_64'
$scene = 'RedflagForge/assets/scenes/Sun-Temple.redflag'
python tests/capture_material_studio.py --scene $scene --width 800 --renderdoc $rd --exe tmp/emissive-profile/RedflagForge-full-emission.exe
python tests/capture_material_studio.py --scene $scene --width 800 --renderdoc $rd --exe tmp/emissive-profile/RedflagForge-shared-depth.exe
$env:RF_EMISSION_BEFORE = 'tmp/material-reference/Sun-Temple-393ef602ba5c-800'
$env:RF_EMISSION_AFTER = 'tmp/material-reference/Sun-Temple-991fdf640a3d-800'
$env:RF_EMISSION_TIMINGS = '1'
& "$rd/qrenderdoc.exe" --python tests/replay_emission_pass.py
```

运行 `tests/summarize_emission_frames.py`，依次传入两份神庙、两份摄影棚的工作目录，即可重新导出图像和 `pixels.json`。火盆局部截取左上角 (345, 234)、宽 134、高 116 的同一区域，用橙色标出发光 RGB 至少一个分量大于 0 的像素，灰色来自同一帧的面板图。

## OpenGL 灯牌与场景烘焙

在仓库根目录运行 `tests\run_scene_tests.cmd`，会画四块没有直接照明的黑色灯牌。前两块共用网格和发光贴图，各自乘上不同颜色，一次绘制即可画完。后两块分别使用常量和绿色贴图。整组共三次主绘制，四个物体都能独立拾取。另一个测试模型用第一套 UV 读底色，用第二套 UV 读发光图。左半边的红色线性值为 4，右半边的绿色为 0.433594。用错 UV 时，右边也会是红色。[OpenGL 四块灯牌的像素、坐标与材质](opengl.json)

浴室和灯光实验室各用正式 Vulkan 编辑器的“烘焙探针”保存一次。在新进程中重开，关闭 TAA、保持相机静止并将光照图宽度设为 160，记录 48 帧。最后一次面板尺寸改变后还剩 47 帧。两个场景在没有烘焙文件时均重画了 32 帧，读回新文件后各重画 1 帧，后 46 帧沿用已有结果。场景的正式设置保留了 TAA。[编辑器版本、两份探针文件摘要与时间线计数](scene-bakes.json)
