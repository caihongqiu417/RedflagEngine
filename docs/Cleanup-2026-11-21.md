# 工程清理记录

本次完成基础清理和资源生命周期修复，不代表全部架构迁移完成。

## 第二轮：资源身份与后处理

- 按 Hazel 的 ShaderLibrary 风格命名 AssetLibrary，头文件声明接口，cpp 实现登记、扫描和查询。
- AssetID 写入模型旁的 `.rfmeta`；ModelRendererComponent 保存 ModelID，场景支持旧 FilePath 迁移。
- AssetManager 使用 ID 缓存。编辑器登记资源，渲染阶段只按 ID 加载，不再逐帧登记路径。
- 在 assets 内移动模型和元数据后，重新打开场景可恢复引用。assets 外的已保存路径只在元数据 ID 一致时恢复，跨盘路径使用 proximate 保留绝对路径。
- 模型卸载同时清空组件 ID、路径和覆盖材质，避免下一帧重新加载；ContentBrowser 隐藏元数据。
- Bloom 和 Tonemap 拆为 PostProcess 实例，独立持有设置、目标、Shader、UBO 和绘制资源。SceneRenderer 其余阶段仍为静态。
- 删除上一轮临时保留的 Core/AssetManager.h 兼容壳；项目已统一使用 Assets 路径。
- 架构文档改为 docs/latex/main.tex + TikZ，旧 Python 生成器移除。输出为 output/pdf/Redflag-Architecture-LaTeX.pdf。
- 资产测试覆盖 ID 持久化、移动、坏元数据、重复 ID、类型校验及缓存所有权；GPU 测试覆盖两个后处理实例的不同曝光、交替渲染、Resize、Bloom 开关和销毁。

以下为第一轮记录，其中尚待实现的稳定 ID 和旧生成入口已经由第二轮替代。
